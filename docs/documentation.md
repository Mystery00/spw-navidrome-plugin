# 文档规范

## 文档分工

| 位置 | 内容 |
| --- | --- |
| `README.md` | 面向用户的项目介绍、下载、支持范围、快速开始与文档入口。 |
| `docs/usage.md` | 账户、播放、缓存、升级卸载和常见问题。 |
| `docs/development.md` | 可复现的构建、测试与发布流程。 |
| `docs/architecture.md` | 当前模块职责、关键设计约束和接口边界。 |
| `AGENTS.md` | 精简的代理工作约定和按需阅读入口。 |
| `docs/plans/` | 设计文档和实施计划，建议命名为 `YYYY-MM-DD-主题.md`。 |

**所有设计文档与实施计划统一放在 `docs/plans/`，不使用 `docs/superpowers/plans/`。** 工具或技能给出其他默认路径时，采用本仓库约定。已有计划只作为历史背景，不能覆盖当前需求和实现。

## 内容与维护

- 中文文档和代码注释，日志使用英文；命令、标识符和协议名保留原文。
- 描述当前可用行为、必要限制和操作方法。临时排查流水账、聊天摘录、逐次安装记录与冗长测试输出不进入长期文档。
- README 不固定插件最新版本，不重复链接当前源码仓库；下载链接指向 Releases 和已发布的工坊条目。工坊未发布时明确标注，不能虚构条目链接。
- 每项事实只维护一个主要位置，其余通过相对链接引用。构建版本以脚本为准，用户必须知道的宿主支持范围仍要明确写出。
- 功能和命令发生变化时同步更新对应文档。移动文件后修正链接，示例使用占位路径与合成账号，不包含开发者本机路径、凭据或认证 URL。
- 发布说明记录面向用户的变化和已知限制；测试结果可在 PR、发布说明或 CI 中呈现，区分自动测试、静态 ABI 检查与实机验收。
- 小修改不强制创建计划；确需计划时记录目标、关键取舍和验收标准，不复制通用代理工作流。

## 代理规范的依据

`AGENTS.md` 参考 OpenAI 的 [Astra 提示与技能实践](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)、[GPT-6 提示指南](https://developers.openai.com/api/docs/guides/latest-model) 和 [AGENTS.md 机制](https://learn.chatgpt.com/docs/agent-configuration/agents-md)。维护重点是项目特有信息、明确完成标准、按需读取和适度验证；不把它扩展成通用教程，也不通过文档强制模型参数。
