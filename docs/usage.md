# 使用说明

安装入口和环境要求见 [README](../README.md)。

## 浏览与播放

在模组配置页切换「专辑」「歌单」，或输入关键词搜索歌曲。专辑和搜索结果分页加载，可通过「加载更多」追加。选择歌曲后点击「播放选中」，整个当前歌曲列表会进入 SPW 原生队列，从所选歌曲开始播放。

歌曲封面按需请求 1024 像素图片，清晰度仍受服务器原图限制。服务器支持同步歌词扩展时优先使用同步歌词，否则回退普通歌词；没有歌词时不影响播放。

拖动依赖服务器对原始音频 Range 请求的支持。插件不承诺实时转码、离线播放或任意位置即时跳转。

## 播放记录

开始实际播放时通过 Subsonic `scrobble` 通知 Navidrome「正在播放」。累计有效收听达到歌曲时长的一半或 4 分钟（取较短者）后提交一次播放记录。该门槛参考 [Navidrome 0.64.2 的官方实现](https://github.com/navidrome/navidrome/blob/v0.64.2/core/scrobbler/play_tracker.go)；插件在达到门槛时提交，不等待停止，并以实际收听时间而非拖动后的进度判断。未知时长采用 4 分钟门槛。

暂停、缓冲、明显拖动和长时间休眠不计入有效收听。同一轮播放只提交一次；暂停继续或拖回开头不重新计次，切到其他歌曲再返回、播放结束后重新开始则作为新一轮。状态每半秒采样，计时存在小幅采样误差。

正在播放通知会在恢复播放时及播放期间定期刷新；标准接口没有暂停清除通知，服务器上的正在播放显示可能延迟消失。记录归属于当前连接账号；Navidrome 若配置了 Last.fm 等服务，可能继续向这些服务转发记录。

网络失败不打断音频播放，会提示上报失败。为避免请求已成功但响应丢失造成重复计次，同一轮失败记录不自动重试；没有持久化离线补报，断开或禁用会取消尚未发送的记录。

## 账户与凭据


服务器地址可以包含反向代理子路径，不要追加 `/rest`。HTTPS 使用正常证书验证，不提供跳过证书校验的选项。

只有连接成功后才保存登录信息。服务器、账号与 HTTP 选择作为普通元数据保存，密码由 Windows DPAPI 当前用户范围保护；加密失败不降级为明文。凭据位于宿主提供的数据目录：

```text
workshop/data/vip.mystery0.spw.navidrome/credentials.json
```

禁用插件或关闭 SPW 会释放会话，但保留加密凭据供下次恢复。更换 Windows 用户后无法解密时，请重新登录。不要手工复制或编辑凭据文件。

右上角「账户管理」可重新配置连接；「退出并忘记」经确认后断开会话并删除保存的登录信息。

## 缓存

音频缓存位于 `%LOCALAPPDATA%\SPW-Navidrome\audio-cache`，容量上限为 512 MiB。界面提供清理入口；缓存仅供当前会话使用，退出账户、禁用或重启时清理，不是离线音乐库。

## 升级与卸载

优先通过 SPW 模组管理导入新版并完成启用确认，不要覆盖正在运行的插件文件。卸载使用模组管理的删除入口，按需要勾选清理数据。

手动维护前先正常退出 SPW。备份插件目录应移到 `workshop/plugins` 之外，避免同一插件存在多个版本；不要删除整个 SPW 用户数据目录或手工改写 `enabled.txt`。

使用过早期开发包 `io.github.mystery00.spw.navidrome` 的用户，应先移除旧插件及其数据，再安装当前插件并重新登录；两个标识之间不迁移凭据。

## 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 配置页只显示权限说明 | 停用后重新启用，授予「允许修改应用行为与界面」权限。 |
| 升级 SPW 后无法使用 | 检查插件支持的宿主版本，等待对应适配；不要强行绕过版本检查。 |
| 连接失败 | 检查根地址、反向代理路径、账号和证书；HTTP 连接需要显式允许。 |
| 自动登录失败 | 在账户管理重新输入并连接；加密凭据只能由原 Windows 用户解密。 |
| 没有封面或歌词 | 先检查服务器是否提供该歌曲对应内容；低清原图不会因请求尺寸增加而变清晰。 |
| 拖动后等待较久 | 检查网络和服务器 Range 支持；未缓存区间需要重新请求上游。 |

网络错误可在页面重试。反馈时只提供脱敏错误，不附凭据或认证 URL。
