# 动态宿主适配与 Navidrome 主菜单入口

## 目标与边界

依照用户提供的开发建议，以反射、Kotlin Metadata 保留的语义和结构签名定位宿主成员，消除写死的混淆类名、方法名、字段名。现有原生播放、封面、歌词、主题、播放记录行为保持一致；左侧主菜单新增 Navidrome 入口，复用当前页面和登录会话，模组配置入口保留。

不将“能解析”声明为所有未来版本已兼容。实际验证基线仍为 Windows SPW 1.19.2；结构或语义变化时明确报告能力不可用，禁止选择第一个模糊候选继续运行。不提交、推送或安装，除非用户另行授权。

## 设计

- 从宿主稳定公开类型、对象字段和 Metadata 建立受限候选集合；不使用混淆名白名单或变相编码映射。
- 解析原始属性／函数语义及 JVM 成员签名，并联合参数、返回类型、接口与所有权校验。对确无 Metadata 的对象，只有结构可唯一证明时才绑定。
- 初始化时解析并缓存反射句柄；播放采样和 Compose 重组不得重复扫描整个宿主包。
- 播放、展示、主题、配置页和侧栏分别界定能力。侧栏失败不能使现有配置入口失效；停用清理本插件全部句柄。
- 主菜单只新增入口，不替换整个侧栏，不更改曲库数据库。点击导航到本插件页面，使用原有 NativeState。

## 实施与验收

1. 为动态解析器增加测试：混淆名称变化仍定位同一语义，参数或返回类型不符拒绝，缺失／多个候选拒绝；观察失败后实现。
2. 重构 Java 宿主适配与封面歌词桥，移除版本精确锁及混淆常量，保留能力检查。使用真实宿主离线解析验证所有句柄，不读取用户凭据、不控制播放。
3. 重构主题及配置页 Hook 的定位，再添加侧栏入口和导航。测试安装失败回滚、重复启停、入口与配置页共用状态以及侧栏失败的独立降级。
4. 更新构建测试入口与使用、开发、架构文档，清除过时的版本锁说明；在源码中检查残留混淆名。
5. 执行协议和会话回归、动态解析测试、实际宿主适配检查、Compose 构建与独立构建，检查安装包依赖隔离。运行结果与实机 UI 验收分开报告。

## 审查重点

- Kotlin Metadata 可能缺失、被裁剪或不保留预期名称；失败需说明具体能力，不回退写死混淆名。
- 相同类型多个字段、Compose 编译器桥接方法和默认参数可能造成歧义；应过滤合成方法并校验完整结构。
- 反射过程不得触发不必要的宿主单例初始化或扫描真实用户数据。
- Hook 注册部分成功、导航关闭与插件停用不得留下入口或已关闭会话。
- 仅宿主混淆变化可以动态兼容，行为变化仍需验证；不能仅移除版本判断而扩大兼容承诺。
