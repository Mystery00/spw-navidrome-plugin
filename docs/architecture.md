# 架构说明

## 模块职责

Java 源码位于 `src/main/java/vip/mystery0/spw/navidrome`，Kotlin 页面位于对应的 `src/main/kotlin` 包目录。

| 模块 | 职责 |
| --- | --- |
| `NavidromePlugin` | 权限检查、插件启停、页面挂载和资源释放。 |
| `AppSession` | 连接、会话代次、后台请求、宿主调用和切换账户时的隔离。 |
| `net/`、`model/` | Subsonic 认证与 API、受限 JSON 解析、歌曲和歌词模型。 |
| `stream/` | 回环 HTTP 服务、Range 校验、完整区间缓存与容量管理。 |
| `host/` | 版本专属的原生队列、流拦截、封面与歌词适配。 |
| `credentials/` | Windows DPAPI 当前用户加密及原子凭据存储。 |
| `playback/` | 有效收听计时、播放代次去重和 Subsonic 上报事件生成。 |
| `ui/` | Compose 页面、异步页面状态、宿主主题与请求隔离。 |

## 宿主边界

插件仅申请 `class-transform` 权限，通过官方 UI Hook 在自己的配置入口显示页面。未授权时仅保留标准配置说明，不启动会话或恢复登录；停止插件时释放自己注册的句柄与资源。

原生播放仍依赖受支持版本的内部签名。`Host1192`、`HostAbi1192`、`NativePresentation` 和 `HostTheme` 是升级宿主时的重点核对位置。使用实际宿主文件验证签名，不能凭公开 API 编译成功扩大兼容范围。

当前适配 API 没有外部音乐源注册能力。专辑、歌单和搜索列表是临时浏览层，不写入 SPW Track/Playlist 数据库，也不向宿主全局曲库保存临时回环 URL。公开音乐源 API 可用后，优先复用现有认证、协议和取流模块替换浏览接入方式。

## 音频与缓存

Navidrome 原始音频通过仅监听 `127.0.0.1` 随机端口的服务交给 SPW。随机路径只映射当前会话登记的歌曲，不接受任意上游地址。

请求采用 `format=raw`，逐次校验并转发 200/206/416；上游忽略 Range 时保持 200。音频边接收边输出，只有完整且长度正确的响应区间才提交缓存，不合并重叠区间，也不伪造完整文件。

缓存容量包括正在写入的保留空间；单响应超过 16 MiB 或长度未知时继续流播但不缓存。缓存按服务器、账号、歌曲、格式、码率和区间隔离，没有主动预取。

## 并发与数据保护

播放记录在宿主串行线程读取一致的当前曲目、播放代次、正在播放状态及毫秒进度。代次来自原生 source session：暂停和普通 seek 保留，重新加载、循环和结束后重播会更换。读取不一致时暂停计时，保留已提交标记，防止重复计次。

`PlaybackTracker` 使用位置增量与单调时钟间隔累计有效收听，排除停顿和跳转。`AppSession` 只上报本会话提交的歌曲，将通知交给独立串行网络线程，队列最多 32 项；会话切换清空待发送队列并关闭旧客户端。网络错误和队列满不阻塞宿主，不自动重试可能已成功的计次请求。播放记录与封面歌词维护独立的歌曲索引，元数据失败不关闭上报。

网络、图片解码、歌词解析和凭据操作在后台执行。宿主提交经过串行调度；页面回填及媒体更新检查请求、媒体实例和会话代次，防止取消、切歌或切换账号后的迟到结果覆盖新状态。

当前曲元数据按需加载，内存最多保留 24 首；每首封面最多 4 MiB、歌词最多 256 KiB，切换账户时清空。主题从宿主 CompositionLocal 获取，随组合更新，不轮询系统主题。

凭据存储失败时保留旧文件，不回退明文。日志不包含密码、认证 URL 或密文内容。插件代码保持适配宿主裁剪后的 Java 运行时，不引入依赖完整 JDK 模块的生产路径；测试可使用完整 JDK 的 HTTP 服务。
